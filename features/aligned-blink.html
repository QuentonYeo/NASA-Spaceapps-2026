Aligned Blink

Compare SPHEREx observations of the same sky field in place, using a common sky grid and a fixed brightness scale. The feature helps a person look for a source that shifts relative to nearby stationary stars.

Using the viewer

  1. Open the local viewer, choose a target such as M101 / Pinwheel galaxy, and select Find observations.
  2. Choose View → Aligned blink. Select a Reference frame. When a compatible comparison is available, the viewer initially picks the frame with the closest reported wavelength at the target. If no wavelength comparison is possible, it falls back to the first compatible frame in timeline order.
  3. Choose a Frame to add and click Add frame. Repeat to build a longer sequence. Frames are appended in the order chosen. Select a frame number in the comparison table to show it, or remove any appended frame. Changing the reference rebuilds the selection around that reference.
  4. Choose Play blink to loop through the sequence at 650 ms per frame. Use Previous, Next, or the arrow keys with the image focused to step manually. The display size stays fixed while switching frames.

The selected-frame comparison table keeps each frame in playback order and highlights the one on screen. It shows UTC observation time, visit, detector, release, and wavelength at the target. Missing wavelength values are labeled unavailable. The table lets you compare timestamps and wavelengths during playback.

What changes between the archive and the screen

Field of view and pixel scale

RA and Dec set the cutout center. Field of view sets how much sky the cutout covers. The archive crops native pixels at about 6.15 arcseconds per pixel. A fully covered 0.05° cutout is roughly 29 pixels across and a 0.10° cutout is roughly 59. Wider fields contain more sky pixels. Fit-to-viewer can make a source appear smaller on screen because more pixels fit into the same area. Edge coverage and rounding can affect the dimensions of native cutouts. IRSA cutout documentation

Sky alignment

Native previews preserve the input FITS dimensions. Two native exposures can have the same nominal pixel scale while pointing or rotating differently, so a stationary source can shift in the viewer. Aligned Blink uses each cutout’s celestial WCS to reproject calibrated brightness values with bilinear interpolation onto a common north-up grid centered on the query at 6.15 arcseconds per pixel. Masked or uncovered pixels are transparent where interpolation has no valid result. Renderer

Brightness and quality

Auto per frame derives black and white points from each frame’s valid 0.5th and 99.5th percentiles. Locked by detector uses the first usable non-flat frame to fix the limits for its detector, release, and brightness unit for that search. Aligned previews use those shared limits. They can look identical to Auto when the frame set the limits or when a later frame has a similar brightness distribution.

The renderer clips to the display limits and applies an asinh stretch before encoding 256 gray levels. PNG compression preserves the resulting image. Brightness precision is lost during clipping and quantization, and aligned reprojection also resamples the original spatial values. When quality arrays are available, the renderer masks selected instrument artifacts and pixels with nonfinite or nonpositive variance. Source and transient flags are preserved. Mask and preview implementation

What makes a frame eligible

The picker checks each candidate against the reference. A candidate needs all of the following:

  • A loaded, ready preview with an aligned image, an aligned grid, and shared display limits.
  • The same detector and release as the reference.
  • Matching black and white points.
  • An observation timestamp different from the reference’s timestamp.
  • A frame ID distinct from the reference and every frame already in the blink list.

Wavelength proximity ranks the default comparison. There is currently no wavelength tolerance or bandpass-overlap filter for added frames. Add frame is disabled when the picker has no eligible loaded frames left. If only three eligible observations have loaded including the reference, two can already be in the default sequence, leaving one to add. More eligible frames can appear as additional cutouts load. Viewer selection and playback logic

Why adjacent timeline frames can be ineligible

The backend queries IRSA SIA at the target coordinates with a 1-arcsecond search radius. It uses DR1 by default and can be configured for other collections. It deduplicates by archive observation ID and sorts by observation time. The requested field of view is passed to the cutout service. Cutouts load in batches, and the frontend merges them into one chronological timeline across detectors. A visit groups observations by time gap, with a new visit after a gap greater than 10 days by default. Archive search · Batching and visits · Timeline sorting

What the detectors measure

SPHEREx splits incoming light into shorter- and longer-wavelength paths. Two detectors can therefore image the target at the same timestamp. Each detector covers a distinct infrared range, and the measured wavelength varies across each detector because its filter changes with position. The viewer shows wavelength at the target when the cutout has usable spectral WCS. Even within one detector, a stationary object can change in apparent brightness as the wavelength changes. Validation and limits

A live M101 pair from D6 produced aligned 59 × 59 previews with shared contrast. A synthetic regression check verified that a shifted source maps to the same output pixel and that missing pixels stay transparent. Chrome checks covered manual switching, playback, appending, removing, and avoiding duplicates.

The earlier M101 investigation compared six pairs using an 80% wavelength-band overlap criterion and found one qualifying pair, at 1.506 and 1.503 µm at the target. Its initial alignment used nearest-neighbor sampling and left residual centroid offsets of 0.12–0.39 pixels among four reference-star candidates. The brightest star left a positive-negative residual. These measurements describe the investigation pair and its processing, while the current viewer uses bilinear reprojection. M101 image-processing investigation

For visual review, follow a candidate’s position relative to nearby stars across several frames at similar wavelengths. Brightness changes can also come from wavelength, background, noise, masking, and clipping. The current feature uses sky-coordinate alignment and shared contrast. Background subtraction, bandpass matching, subpixel registration refinement, and a current residual accuracy measurement are pending.

For AI detection or quantitative measurements, use calibrated FITS brightness arrays, variance, masks, and WCS. Compare registered arrays on a common grid for pixel-level detection, or detect on the native arrays and link detections in RA and Dec. Future UI work discussed includes an interactive FITS-backed brightness stretch, candidate displacement in arcseconds, and a difference overlay after verifying registration and matching stellar profiles.
