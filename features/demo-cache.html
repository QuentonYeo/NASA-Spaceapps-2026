Prepared demo cache

The eight Known Objects presets and two suggested Explore fields share a catalog in shared/demo-examples.json. Prepared snapshots let these exact searches replay local observations without contacting IRSA discovery or downloading their previews again.

Prepare before a demonstration

From backend/, run uv run python -m scripts.prepare_demos --import-only to copy usable saved searches into the demo cache without network access. Then run uv run python -m scripts.prepare_demos to download missing frames, native FITS and Gaia reference data. Repeat the command to resume. --only vesta arosa m101 barnard limits preparation to the four Validate examples. --provider s3 explicitly selects the existing anonymous S3 adapter instead of IRSA HTTP cutouts. The default uses the configured CUTOUT_PROVIDER.

Use uv run python -m scripts.prepare_demos --status to inspect each snapshot. The report distinguishes preview playback readiness, retained native science counts, and Gaia readiness. A complete preview set can replay while science or Gaia is still missing; it is not a fully offline science dataset. The default preparation budget is ten minutes, checked between frames; a current archive request can finish after that budget. Every successful frame is saved immediately.

When native FITS is recovered for a legacy preview-only snapshot, preparation regenerates native and aligned previews from those exact retained pixels, preserving the shared display limits. This keeps region overlays and source measurements on the same crop and WCS as the displayed image.

Routing and retention

Preparation first queries the ESA Gaia TAP service. If that service is unavailable, it can use the CDS VizieR Harvard mirror of Gaia DR3 (I/355/gaiadr3). Mirror positions remain ICRS at reference epoch 2016.0; pmRA maps to the RA proper motion including cos(dec), pmDE to declination proper motion, and missing motions remain null. Catalogue provider, query URL and reference epoch are saved as snapshot provenance. This fallback applies to preparation only; live Gaia routing is unchanged.

Snapshots live in backend/.cache/demos/, configurable through DEMO_CACHE_PATH. They are separate from the ordinary expiring search cache and are retained until explicitly removed or rebuilt. They contain previews, aligned grids, display limits, exposure provenance, any retained FITS, completed analysis and Gaia data when prepared. Each replay receives its own sequence ID.

An exact catalog match of coordinates and FOV can replay a complete snapshot in both Known Objects and Explore. Explicit exposure selections must match the curated set. Detector filters select matching saved exposures; unmatched detectors or changed regions use the live route. Motion-search requests use the live analysis route and can reuse matching bundled FITS. Reload field for analysis bypasses snapshot replay and performs live discovery; exact-region FITS files already in the bundle are still reused. A saved full-field search can supply the selected exposure subset of a Validate example.

Limits

Preparation still depends on archive availability for missing data. Interrupted or failed downloads remain resumable; they do not produce a complete snapshot. Cached science is required for offline photometry. Spectrum extraction for an arbitrary stationary region still uses the separate mosaic cube cache and is not preloaded by this command. Reference catalogues that could not be prepared can still require a live lookup. Old preview-only searches do not contain recoverable science pixels.

FITS cache · Viewer workflows

The application backend loads DemoStore during startup and checks matching prepared snapshots before archive discovery. The frontend shows when a prepared snapshot is used. This integration does not change the native or aligned image rendering. Preview completeness and science completeness are separate: an incomplete preview snapshot falls back to live discovery; preview-only snapshots still need remote science for analysis.

Tracked Known Objects data

The application automatically reads demo/known-objects/frames.sqlite3 from the repository as a read-only fallback. It contains 1,256 previews and matching compressed native FITS files for all eight presets: Vesta (3), Arosa (8), M101 (2), Barnard’s Star (2), WISE 0855 (258), RW Aurigae (226), R Draconis (413), and Epsilon Indi B (344). No database copy, extended runtime-cache TTL, or preloaded frontend mode is required for ordinary queries. Runtime checkpoints and locally prepared demos stay separate and writable. The shared catalog keeps frontend and backend coordinates synchronized.

Explore queries at the exact saved coordinates and FOV reuse these observations without archive discovery. The four curated examples contain selected exposures rather than every observation in that field; Explore identifies this scope and offers Search full archive field. A full-field search still discovers any additional exposures, using bundled native FITS for matching exposure IDs and the exact region, and fetching other cutouts normally. Nearby coordinates or different FOV values do not match. Spectrum cubes and uncached Gaia catalogues remain separate dependencies.

The repository also includes six original Gaia catalogues, two older prepared-field snapshots, and 222 additional native FITS cutouts under demo/additional-observations. Exact region and exposure keys control reuse; these additions do not imply complete field coverage. The spectrum cache is separately packaged under demo/spectrum-cache and automatically restored on first spectrum use.
