FITS cutout cache

Reuse downloaded SPHEREx pixels across searches in the same backend process. The archive release and its exposure ID identify the source. Each cached cutout has its own requested region and keeps the original FITS sky-coordinate metadata.

How a search uses the cache

  • An identical region reuses its downloaded cutout.
  • For a smaller or nearby view, the backend projects the requested sky grid into the cached FITS coordinates. If that grid fits, it crops the native image and quality mask, keeps surrounding pixels for interpolation, and builds previews for the new view.
  • If no cached cutout covers the view, the backend requests the cutout from the archive. Wavelength at the new target is evaluated using the original FITS metadata when available.

Limits

The cache defaults to 128 MiB of FITS data and evicts the least recently used cutout first. Set CUTOUT_CACHE_BYTES=0 to disable it. The cache lives in memory and clears when the backend restarts. Observation discovery still runs on each new search. The browser remembers the last accepted search in the same tab. Refresh reconnects to the existing backend job and reloads its previews. Submitting identical coordinates and field of view in that tab also reuses the job. Completed batches are also saved to a local SQLite cache. After restart, the saved job ID can replay its frames and resume at the next batch. Checkpoints are retained for up to seven days, subject to a 256 MiB compressed payload budget. If the checkpoint is unavailable, the viewer keeps the inputs and prompts you to search again. Blink selections still reset on refresh. A restart during a batch can require rerunning that batch. The disk cache stores previews and job metadata. Raw FITS caching stays in memory.
