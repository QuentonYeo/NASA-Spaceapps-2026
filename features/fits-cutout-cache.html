FITS cutout cache

Reuse downloaded SPHEREx pixels across searches in the same backend process. The archive release and its exposure ID identify the source. Each cached cutout has its own requested region and keeps the original FITS sky-coordinate metadata.

How a search uses the cache

  • An identical region reuses its downloaded cutout.
  • For a smaller or nearby view, the backend projects the requested sky grid into the cached FITS coordinates. If that grid fits, it crops the native image and quality mask, keeps surrounding pixels for interpolation, and builds previews for the new view.
  • If no cached cutout covers the view, the backend requests the cutout from the archive. Wavelength at the new target is evaluated using the original FITS metadata when available.

Limits

The cache defaults to 128 MiB of FITS data and evicts the least recently used cutout first. Set CUTOUT_CACHE_BYTES=0 to disable it. The cache lives in memory and clears when the backend restarts. Observation discovery still runs on each new search. The browser remembers the last accepted search in the same tab. Refresh reconnects to the existing backend job and reloads its previews. Submitting identical coordinates and field of view in that tab also reuses the job. Completed batches are also saved to a local SQLite cache. After restart, the saved job ID can replay its frames and resume at the next batch. Checkpoints are retained for up to seven days, subject to a 256 MiB compressed payload budget. If the checkpoint is unavailable, the viewer keeps the inputs and prompts you to search again. Blink selections still reset on refresh. A restart during a batch can require rerunning that batch. The disk cache stores previews and job metadata. It also stores compressed native FITS inputs by sequence and frame ID under a separate 1 GiB budget. The archive cutout cache used for coverage reuse stays in memory.

Aligned Blink · Backend cache implementation

Native spectrum selection uses retained FITS in the displayed preview grid. Reusing a larger cutout preserves cropped science planes, shifts primary and alternate reference pixels, and keeps wavelength lookup tables intact. New disk checkpoints also restore native science within the disk budget. Older preview-only checkpoints still report the missing data. In Explore, Reload field for analysis fetches the field again when a saved search is missing FITS inputs.

Search jobs have no default count limit; two sequence workers execute jobs while additional searches queue. Completed in-memory jobs expire after 120 seconds (configurable with JOB_TTL_SECONDS), while disk checkpoints keep their separate seven-day retention. MAX_JOBS remains an optional deployment limit. Search creation retries explicit retryable 429/503 rejections at most three times with delays capped at ten seconds. Requests have a 20-second timeout and polling retries transient failures three times. A timed-out creation request is not automatically repeated because it may already have created a job. Worker concurrency and cache byte budgets still apply.

A cleanup worker removes expired completed jobs without waiting for another request. A search waiting for a download worker expires after 15 seconds (checked every second); this deadline does not apply to running IRSA requests. Identical in-flight queries from one browser tab reuse their job. A newer query from that tab cancels queued older work and prevents further frame downloads for superseded searches; already running network calls finish under their existing network timeouts. Other tabs are independent. There is no default job-count limit, so concurrent unique searches from many tabs can still grow the queue.

The tracked Known Objects database is read only. Exact-region queries in Explore can use its previews and native FITS immediately, and the live cutout provider also reuses its science files when both exposure ID and region match. Refresh requests still discover the archive inventory but do not redownload those matching FITS files. Curated exposure subsets are identified in Explore and never presented as a complete field inventory.

Additional repository assets preserve 222 local native FITS cutouts beyond the Known Objects snapshot. The live provider reads these immutable files by exact exposure and region. A separate split archive preserves cached spectrum cube/range data, with checksum verification and writable-cache restoration on first spectrum use.

Explicit reload actions send refresh=true to bypass preview-only prepared demos. Cached native images lacking selection coordinates expose a Reload field for selection action directly in the viewer. Routine searches do not force refresh.
