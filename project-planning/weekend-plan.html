NASA Space Apps Challenge · 14–15 November 2026

SPHEREx Sky Blink

Build a public viewer that blinks through real infrared observations of one patch of sky, flags possible motion, and lets visitors inspect the evidence for themselves. Demo targets are the challenge’s five: Barnard’s Star, Epsilon Indi B, WISE 0855−0714 (RA 08h55m10.831s, Dec −07°14′42.53″), RW Aurigae and R Draconis.

Implementation update - 14 November

API and viewer integration: the backend now discovers and deduplicates DR1 exposures, groups visits with a configurable 10-day gap, fetches cutouts through selectable IRSA/S3 adapters, and delivers inline PNGs through polling. It downloads 12 frames per batch; the viewer automatically requests subsequent batches until all exposures have results. Stop/Resume controls preserve received images and the polling cursor; an already running backend batch may finish. The basic viewer has sky inputs, progress, frame navigation, native/4x/fit display controls, and WISE 0855/M101 presets.

Image-processing handoff: current PNGs are temporary native-grid previews. Masking, background estimation, alignment, differences, shared display scaling and scientific exports remain the image-processing workstream's responsibility. The S3 preview adapter currently reads IMAGE and spatial WCS only; retrieval must preserve the additional arrays and metadata required by that developer.

Quality issue to address: some exposures look much noisier than others. The renderer independently stretches each frame and does not use FLAGS, VARIANCE or local wavelength. Compare like wavelengths, expose quality summaries and use a documented display policy before interpreting changes. Screenshots alone cannot establish whether a difference is noise, an artifact or real variation. Do not mask every nonzero flag: some flags identify sources rather than unusable pixels.

Validated: 23 backend tests, 7 frontend unit tests and 8 desktop/mobile browser checks. An eight-exposure local benchmark measured fresh IRSA 47.0 s, pooled IRSA 16.4 s and S3 range reads 6.3 s; this is one sample, not a performance guarantee. Jobs remain process-local; durable jobs, cancellation and cached demo fallback are still outstanding.

Four parallel workstreams

1. Archive and fixtures

  1. In backend/notebooks/, query IRSA SIA2 for single exposures from spherex_dr1 (DR1 only: QR3 returned no frames for WISE 0855). Save example metadata and record which fields carry IDs, dates and download URLs. Started: find_frames.py. SIA2 took ~1.7 s vs 9–21 s for TAP (same 258 frames); access_url is the source link.
  2. Use IRSA MOST to locate exposures covering a known asteroid’s predicted positions. Download FITS cutouts centered on a common sky patch. Verify actual shared coverage, target visibility, comparable local wavelengths and distinct times.
  3. Write a small SPHEREx adapter in backend/app/services/ with search and cutout steps. Validate RA, Dec and FOV, enforce server-side limits on FOV and frame count, and cache by sky region, release and selection parameters. Make errors and partial coverage visible.

Handoff: reproducible fixtures for the five challenge targets with source links, plus a cached demo selection. IRSA archive access · MOST

2. Image processing

  1. Read IMAGE, FLAGS, VARIANCE and coordinate metadata. Select documented flag bits to mask. Estimate a local background and record the method. Keep invalid and uncovered pixels masked through alignment.
  2. Align frames to one sky grid using the image coordinates. Compare clean reference stars to check alignment. Compute pairwise signed difference images only over common valid coverage at comparable wavelengths. Inspect residuals around bright stars before using them as detection evidence.
  3. Export a common-scale preview and difference overlay for the UI. Keep calibrated arrays and masks for detection. Retain FITS provenance so an exported image can be traced to the archive.
  4. Long-baseline blink: fetch 2MASS (~2000) and AllWISE (~2010) images on the same grid with astroquery.hips2fits, so WISE 0855 and Barnard’s Star visibly move over 25 years.

Handoff: arrays, display frames, and a shared grid with documented dimensions and orientation (north up, east left, origin top-left: row 0 is the north edge). SPHEREx data products

3. Viewer and integration

  1. In frontend/, build a custom viewer (not Aladin Lite) and load the fixture on startup. Build RA, Dec and FOV inputs, play/pause, frame selection, zoom and contrast. Contrast applies across the sequence and zoom preserves the view when changing frames.
  2. Show time, local wavelength, release, loading and missing or partial coverage. Put 2MASS and AllWISE frames on the same timeline for the long-baseline blink. Add frame selection for detection and toggleable difference, candidate and known-object overlays. Draw markers in processed frame coordinates and apply the same zoom transform as the image.
  3. Connect FastAPI live search with a visible path back to the demo. For known stars, use Gaia DR3 positions propagated to the frame epoch where proper motion is available. For the verified asteroid, use MOST predictions at each exposure time.

Handoff: a complete browser workflow exercised against the same manifest in cached and live modes. Gaia DR3

4. Candidate detection

  1. Start with a baseline. Find point-like peaks in cleaned images or difference overlays, then link plausible positions across selected frames. Score repeat detections, signal relative to noise, track consistency and distance from flagged pixels. Describe two-frame results as tentative.
  2. Return candidate ranks with frame IDs, marker positions and evidence. Validate against the held-out asteroid predictions after ranking. Record tolerances in pixels or angular distance and inspect the strongest artifacts.
  3. If there are enough labeled tracks, train a small classifier on the same features and compare with the baseline on a separate field. Report both ranks and false leads. Show users whether the active ranking is rules-based or learned.

Handoff: ranked candidates, evidence overlays and a short recovery report. Unmatched tracks remain candidates for review.

Shared contract for the first integration

Use the existing Python/FastAPI backend and React/TypeScript frontend. The backend handles archive queries, coordinates, processing and detection. The frontend renders aligned images and overlays. Start with a JSON fixture so both sides can work in parallel.

Sequence { id, centerRaDeg, centerDecDeg, fovDeg, grid, frames[] }
Grid     { width, height, orientation }
Frame    { id, observedAtUtc, release, detector, wavelengthUm,
           previewUrl, sourceFitsUrl, coverage, status }
Candidate { id, rank, score, method, reasons[], detections[] }
Detection { frameId, xPx, yPx, raDeg, decDeg }

Use UTC ISO timestamps, ICRS coordinates in degrees, and micrometres for wavelength. Store preview pixels with a top-left origin; the backend grid already uses it, so array indexes, PNG pixels and xPx/yPx are the same numbers. Define wavelengthUm at the sequence center and label it as such. Use wavelength at the source position for candidate comparisons where available. Represent unknown values as null and give incomplete frames an explicit status. Archival frames use release "2MASS" or "AllWISE". Keep raw FITS, variance and masks on the backend. Keep the asteroid prediction overlay available as a separate reveal.

Suggested routes. GET /api/demo serves the cached manifest. GET /api/frames takes RA, Dec and FOV and returns the same manifest shape. POST /api/detect takes a sequence ID and selected frame IDs and returns ranked candidates. A cached demo can ship with precomputed candidates if on-demand processing is still slow.

Scope decisions

Ship first

Time playback at comparable wavelengths, zoom and contrast, frame metadata, aligned real sequences for the five challenge targets, the long-baseline blink (2MASS → AllWISE → SPHEREx) and a candidate reveal. Use live IRSA search for a bounded request. If live access fails during judging, use the cached sequence and show its provenance.

Add once the demo works

Try a wavelength navigator grouped into six detector bands, with gaps visibly disabled. For wavelength browsing, use DR1 All-Sky Cube channels or exposures from a chosen time window. Label a cube view as combined observations. For a spectrum, plot brightness against wavelength at a selected sky position using a cube or calibrated measurements across exposures.

Keep as stretch goals

Add shareable URL state for region, mode and selected frame, then document embedding. Use the sequence manifest as the boundary for another archive or a user-supplied overlay. Start with one documented import format and validate coordinates and units before adding plugins.

Defer molecular maps

Mapping methane, water or CO₂ requires validated spectral features, a continuum estimate and uncertainty checks. If you build the spectrum panel, use annotated feature wavelengths as an educational aid while the team evaluates whether the data support a map.
